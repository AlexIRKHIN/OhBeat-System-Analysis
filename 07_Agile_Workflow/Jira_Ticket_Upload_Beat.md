## 2. User Story

> **Как** зарегистрированный Продюсер платформы,  
> **я хочу** заполнить метаданные, загрузить медиафайлы и задать цены на лицензии в единой форме,  
> **чтобы** мой бит после автоматической проверки появился в каталоге и стал доступен для покупки Артистами.

---

## 3. Критерии приемки (Acceptance Criteria)

### AC-1. Валидация метаданных
* Название является обязательным полем, длина от 3 до 60 символов.
* Поле BPM принимает только целые числа в диапазоне от 40 до 300. Ввод букв, спецсимволов и отрицательных значений заблокирован на уровне UI.
* Тональность является обязательным полем (выбор из выпадающего списка), значение по умолчанию не выбрано.
* Жанры — множественный выбор от 1 до 3 значений. После выбора третьего жанра добавление новых блокируется.

### AC-2. Выбор и предпроверка файлов
* **Дано:** Продюсер выбирает файл обложки.
  **Когда:** выбран файл формата JPG, PNG или WebP, размером до 5 МБ и с соотношением сторон 1:1.
  **Тогда:** в UI мгновенно отображается миниатюра обложки.
* **Дано:** Продюсер выбирает файл в зону «Master WAV».
  **Когда:** выбран файл в формате MP3 или размер файла превышает лимит в 200 МБ.
  **Тогда:** появляется красное системное уведомление «Неверный формат или превышен размер файла», процесс загрузки блокируется и не начинается.
* **Дано:** в сетке лицензий активна лицензия `Trackout` или `Exclusive`.
  **Когда:** ZIP-архив со стемами не выбран.
  **Тогда:** кнопка публикации неактивна, под зоной ZIP-архива выводится подсказка «Нужен для Trackout и Exclusive».

### AC-3. Настройка лицензий и цен
* В сетке лицензий всегда отображаются 4 фиксированные строки: Basic, Premium, Trackout, Exclusive.
* Как минимум одна лицензия должна быть отмечена активной.
* При снятии чекбокса активности с лицензии соответствующее поле цены блокируется для ввода.
* Цена активной лицензии должна находиться в строгом диапазоне от 100 до 500 000 ₽.

### AC-4. Процесс отправки и состояния UI
* Главная кнопка «Опубликовать бит» остается неактивной до тех пор, пока не будут успешно выполнены условия AC-1, AC-2 и AC-3.
* По нажатию на кнопку форма блокируется от изменений, внутри кнопки отображается спиннер.
* При получении ответа `201 Created` от Core API файлы начинают загружаться в объектное хранилище S3 параллельно. Для каждого файла отображается индивидуальный прогресс-бар.
* При обрыве интернет-соединения в процессе загрузки пользователю выводится уведомление (toast) и активируется кнопка «Повторить» для незагруженных объектов.
* После получения ответа `202 Accepted` на финальный запрос подтверждения (confirm) выводится зеленое уведомление «Бит загружен и обрабатывается», происходит автоматический редирект в раздел «Мои биты», где новый трек отображается со статусом «Обработка» (`processing`).

### AC-5. Обработка серверных ошибок
* При получении ответа `400 VALIDATION_ERROR` система подсвечивает проблемные поля, указанные в массиве `details`, и выводит текст ошибки непосредственно под соответствующим инпутом.
* При получении ответа `422 FILES_MISSING` система явно указывает пользователю, какой именно файл не был найден в S3 и требует повторной загрузки.

## 4. Декомпозиция (Technical Tasks)

Для реализации данного User Story выделены следующие технические подзадачи с распределением по командам:

| Ключ | Команда | Описание задачи |
| :--- | :--- | :--- |
| `OHB-143` | Backend | Эндпоинт `POST /v1/beats`: реализация строгой валидации полей, проверка по стоп-листу слов, сохранение бита в статусе `uploading`. |
| `OHB-144` | Backend | Интеграция с S3: генерация ссылок presigned POST с применением политик `content-length-range`, настройка lifecycle-правил для бакета `temp-uploads` (удаление через 24 ч). |
| `OHB-149` | Backend | Эндпоинт `POST /v1/beats/{id}/confirm`: реализация запроса `HeadObject` в S3, атомарная смена статуса на `processing` и инсерт события в таблицу `outbox` в рамках одной транзакции СУБД. |
| `OHB-145` | Frontend | Верстка экрана загрузки бита в Producer Dashboard в соответствии с макетами Figma. |
| `OHB-146` | Frontend | Реализация клиентской логики: валидация инпутов (AC-1, AC-3), проверка файлов до загрузки (AC-2) и реактивное управление состоянием кнопки публикации. |
| `OHB-147` | Frontend | Реализация параллельной прямой загрузки файлов в S3 по presigned POST политикам, отслеживание прогресса загрузки (progress events), логика ретраев при обрыве связи (AC-4).|
| `OHB-148` | QA | Составление тест-кейсов и проведение функционального тестирования (black-box), включая проверку граничных значений лимитов размеров и цен, а также имитацию обрыва сети. |
