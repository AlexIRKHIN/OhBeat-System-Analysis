# 🎵 OhBeat — Музыкальный B2C/C2C Маркетплейс

Комплексная системная спецификация и архитектурное проектирование цифровой платформы дистрибуции музыкальных инструменталов (битов) и безопасного лицензирования прав.

---

## 📌 О проекте

**OhBeat** — специализированный маркетплейс, выступающий гарантом сделок между продюсерами (битмейкерами) и артистами (исполнителями). Платформа автоматизирует полный жизненный цикл: от клиентской загрузки тяжелых медиафайлов и фоновой конвертации аудио до проведения двухстадийных платежей, подписания юридически значимых договоров (ПЭП) и безопасной выдачи архивов.

### Ключевые проблемы предметной области:
* **Для артистов:** Высокие риски нарушения авторских прав при покупке через соцсети, отсутствие прозрачных лицензий и гарантий передачи файлов.
* **Для продюсеров:** Отсутствие гарантий оплаты, уязвимость исходных дорожек (WAV/Stems) к краже до совершения транзакции.

## 🛠 Технологический стек архитектуры

* **Архитектурный паттерн:** Модульный монолит (Core API) + Выделенный асинхронный воркер (Media Worker).
* **СУБД:** PostgreSQL (19 реляционных таблиц, нормализация 3НФ, строгие ACID-транзакции, частичные индексы).
* **Брокер сообщений:** RabbitMQ (Топология Direct Exchange, Transactional Outbox, очереди повторов с задержкой, Dead Letter Queue).
* **Медиа-хранилище:** S3-совместимое объектное хранилище (разделение на временный, приватный и публичный бакеты) + CDN.
* **Интеграции:** ЮKassa (Двухстадийные платежи с холдированием, сплитование, верификация Webhooks, идемпотентность через `Idempotence-Key`), SMS/Email OTP провайдер.
* **Моделирование и стандарты:** BPMN 2.0, UML (Sequence, Use Case, State Machine), REST API (Markdown-контракты), HTTP Range Requests (RFC 9110), 63-ФЗ (Простая электронная подпись), 152-ФЗ (Локализация ПДн).

## 🚀 Архитектурные особенности решения (Deep Dive)

> ### 1. Разгрузка сервера от тяжелого медиатрафика
> Клиент загружает мастер-WAV (до 200 МБ) и ZIP со стемами (до 1 ГБ) напрямую в бакет **S3** через **Presigned POST** с ограничением размера `content-length-range`. Сервер приложений не пропускает через себя гигабайты трафика и подтверждает прием через запрос `HeadObject`.

> ### 2. Изоляция ресурсоемких задач (FFmpeg)
> Нарезка MP3 320 кбит/с и наложение войстегов вынесены в асинхронный **Media Worker**. Команды передаются через брокер **RabbitMQ** по паттерну **Transactional Outbox**, исключая потерю сообщений при сбое брокера.

> ### 3. Защита от состояния гонки (Race Condition)
> При покупке эксклюзива ставится атомарный SQL-резерв на 15 минут в единой транзакции базы данных. Деньги холдируются через двухстадийный платеж **ЮKassa**, а фактическое списание происходит только после повторной проверки статуса бита.

> ### 4. Стриминг аудиопревью (RFC 9110)
> Воспроизведение MP3 организовано через потоковые HTTP Range Requests со статусом 206 Partial Content за CDN. Целевое время первого звука — менее 300 мс (p75 при попадании в кэш CDN), перемотка не требует скачивания трека с нуля, а непрослушанный трафик не расходуется.

> ### 5. Юридическая сила договоров (63-ФЗ)
> Дифференцированный механизм Простой электронной подписи: конклюдентный акцепт оферты для обычной аренды и верификация через одноразовый **SMS/Email OTP-код** для эксклюзивных прав с генерацией штампа подписи и фиксацией SHA-256 хэша.
