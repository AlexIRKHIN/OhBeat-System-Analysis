# 🖥️ Спецификации экранных форм (UI Specifications)

В данном документе зафиксированы требования к пользовательским интерфейсам (UI), клиентской валидации, состояниям элементов управления и маппингу полей экранных форм на параметры REST API и сущности базы данных PostgreSQL.

---

## 1. Спецификация экранной формы: Загрузка бита (Producer Dashboard)

Интерфейс предназначен для авторизованных пользователей с ролью «Продюсер» и служит для публикации нового музыкального инструментала в каталог платформы.

| № | Элемент UI | Тип элемента и валидация на клиенте | Параметр API / поле БД | Поведение и состояния (Комментарий) |
| :--- | :--- | :--- | :--- | :--- |
| **1** | **Зона «Обложка»** | File Uploader. Обязательное; форматы: JPG, PNG, WebP; пропорции 1:1; размер до 5 МБ, разрешение до 2048×2048 px. | `files.cover` → `beat_files` (`kind = cover`) | Превью-миниатюра появляется в интерфейсе сразу после успешного выбора файла. |
| **2** | **Поле «Название бита»** | Input (Text). Обязательное; длина от 3 до 60 символов; автоматический Trim пробелов по краям. | `title` / `beats.title` | Поле подсвечивается красным цветом при потере фокуса (onBlur), если оно пустое или короче 3 символов. |
| **3** | **Поле «BPM»** | Input (Number). Обязательное; целое число в диапазоне от 40 до 300. | `bpm` / `beats.bpm` | Строго фильтрует ввод: блокирует буквы, спецсимволы, знаки минус и дробные значения. |
| **4** | **Выпадающий список «Тональность»** | Select (Combobox). Обязательное; выбор 1 значения из системного справочника. | `musical_key` / `beats.musical_key` | Значение по умолчанию не задано (placeholder: «Выберите тональность»). |
| **5** | **Мультиселект «Жанры / Теги»** | Select (Multiple). Обязательное; выбор от 1 до 3 значений из справочника. | `genres` / `beat_genres` | При выборе 3 жанров выпадающий список автоматически блокируется для новых добавлений. |
| **6** | **Поле «Описание»** | Textarea. Необязательное; максимальная длина до 1000 символов. | `description` / `beats.description` | Поддерживает многострочный ввод; отображается динамический счетчик оставшихся символов. |
| **7** | **Зона «Master WAV»** | File Uploader (Dropzone). Обязательное; формат `.wav`; размер до 200 МБ. | `files.wav` → `beat_files` (`kind = master`) | Отображает динамический прогресс-бар загрузки (0–100%). При неверном расширении или превышении лимита размера система должна немедленно выводить всплывающий алерт без старта загрузки. |
| **8** | **Зона «Stems ZIP»** | File Uploader (Dropzone). Обязательное (если активна лицензия Trackout или Exclusive); формат `.zip`; размер до 1 ГБ. | `files.stems` → `beat_files` (`kind = stems`) | Система должна запускать предварительную проверку размера файла на стороне клиента до начала фактической передачи в S3. |
| **9** | **Сетка «Лицензии»** | 4 жестко заданные строки: Basic, Premium, Trackout, Exclusive. Чекбокс активации + Input стоимости (₽). | `licenses[]` / `beat_prices` | При снятом чекбоксе соответствующее поле ввода цены становится неактивным (`disabled`). Валидация цены: диапазон от 100 до 500 000 ₽. Требуется минимум 1 активная лицензия. |
| **10** | **Кнопка «Опубликовать бит»** | Button (Primary, Submit). Активна только при прохождении валидации полей 1–9. | Вызов `POST /v1/beats` | При клике система должна блокировать форму и выводить спиннер «Отправка…». После получения ответа `201 Created` система инициирует прямую загрузку файлов в S3, по завершении отправляет `confirm`-запрос и перенаправляет пользователя в раздел «Мои биты» со статусом «Обработка». |

## 2. Спецификация экранной формы: Данные покупателя для договора (Billing Details)

Форма предназначена для сбора минимально необходимых юридических и контактных данных Артиста перед формированием лицензионного договора и проведением платежа (с учетом требований 152-ФЗ о минимизации обрабатываемых данных).

| № | Элемент UI | Тип элемента и валидация на клиенте | Параметр API | Поведение и состояния (Комментарий) |
| :--- | :--- | :--- | :--- | :--- |
| **1** | **Радиокнопки «Тип покупателя»** | Radio Group: «Физ. лицо» / «ИП или юр. лицо». Значение по умолчанию: «Физ. лицо». | `payer_type` | При выборе варианта «ИП или юр. лицо» форма должна динамически расширяться вниз, отображая поля организации (п. 5–7). |
| **2** | **Поля «Фамилия», «Имя», «Отчество»** | 3 × Input (Text). Фамилия и имя — обязательные, отчество — опционально. Допускаются только буквы, пробелы и дефисы. | `last_name`, `first_name`, `middle_name` | Система должна автоматически преобразовывать первую букву каждого поля в заглавную (Capitalize). |
| **3** | **Поле «Email»** | Input (Email). Обязательное; валидация по регулярному выражению электронной почты. | `email` | Поле подсвечивается красным при несоответствии стандарту; на этот адрес отправляются купленные файлы и копии договоров. |
| **4** | **Поле «Телефон»** | Выбор кода страны (default: +7) + Input (Tel) с маской ввода. Обязательное для заказов с лицензией Exclusive. | `phone` (формат E.164) | При выборе кода +7 и вводе первой цифры «8» система должна автоматически заменять ее на «+7»; на этот номер поступает OTP-код подтверждения. |
| **5** | **Поле «Название организации»** | Input (Text). Обязательное (только для юрлиц и ИП). | `company_name` | Полное наименование компании (например, ООО «Звук»). Скрыто при выборе статуса физлица. |
| **6** | **Поле «ИНН»** | Input (Text) с `inputmode="numeric"`. Строго 10 цифр для юридических лиц или 12 цифр для ИП. | `inn` | Реализуется как текстовое поле во избежание потери ведущего нуля (ИНН может начинаться с нуля). Включает проверку контрольной суммы. |
| **7** | **Поле «Юридический адрес»** | Input (Text). Обязательное для ИП и юридических лиц. | `legal_address` | Адрес регистрации юридического лица или индивидуального предпринимателя. |
| **8** | **Чекбокс «Согласие на обработку ПДн»** | Checkbox. Обязательное. | `pd_consent` | Содержит активную ссылку на юридическую Политику обработки персональных данных (соответствие 152-ФЗ). |
| **9** | **Кнопка «Сохранить и продолжить»** | Button (Primary, Submit). | Вызов `PUT /v1/users/me/billing` | Кнопка заблокирована (`disabled`), пока все обязательные поля формы не заполнены без ошибок клиентской валидации. |
